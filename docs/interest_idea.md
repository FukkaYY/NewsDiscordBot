# 関心度を記録・利用する機能 - 実装仕様

## 1. データの評価・記録

### 1.1 データベース定義

ユーザーの評価を保存するために、以下のテーブルを追加する。

**テーブル名: `news_ratings`**

| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `url` | TEXT | ニュースのURL（`news_history.url` への外部キー） |
| `user_id` | INTEGER | 評価したDiscordユーザーのID |
| `rating` | INTEGER | 1〜5の5段階評価 |
| `created_at` | TIMESTAMP | 評価日時（重み付け計算に使用）。デフォルトは `CURRENT_TIMESTAMP` |

- **制約**: `PRIMARY KEY (url, user_id)`
  - 1人のユーザーが同じニュースに対して行える評価は1つのみ。
  - 再度ボタンを押した場合は `INSERT OR REPLACE` で値を更新する。

### 1.2 Discord UI

- **形式**: 各ニュースメッセージに `discord.ui.View` を付与し、1〜5のラベルが付いたボタンを表示する。
- **挙動**:
  - ボタン押下時、データベースに評価を保存。
  - 「評価（X/5）を受け付けました」というメッセージを `ephemeral=True`（本人にのみ見える形式）で返信。
- **永続性**: ボット再起動後も過去のニュースのボタンが動作するよう、`setup_hook` で `Persistent View` として登録することを検討する（または最新の配信分のみ有効とする）。

## 2. 関心度の集計と利用

### 2.1 重み付き平均の計算

新しい評価を重視するため、以下のロジックでジャンルごとのスコアを算出する。

- **重み（Weight）**: `1 / (経過日数 + 1)`
  - 本日の評価は重み 1.0、7日前は約 0.125 となる。
- **計算式**: `ジャンル別スコア = Σ(評価値 * 重み) / Σ(重み)`
- **集計頻度**: ニュース配信の直前に、全ジャンルについて最新のスコアを計算する。

### 2.2 ニュース選定アルゴリズム

集計したスコアに基づき、Geminiへのプロンプトを動的に生成する。

1. **ジャンルの分類**:
   - **高関心ジャンル**: スコアが高い上位3位、かつスコアが3.5以上のジャンル。
   - **その他のジャンル**: それ以外のすべてのジャンル。
2. **Geminiへの指示**:
   - プロンプトに現在の「ジャンル別関心度リスト」を含める。
   - 「高関心ジャンルから3件、その他のジャンルから2件、計5件を厳選せよ」と明示的な制約を与える。
3. **フォールバック**:
   - 高関心ジャンルのニュースが検索結果に不足している場合は、重要度（DDGSの適合度）を優先して補填する。

## 3. 実装フェーズ案

1. **Phase 1: 基盤実装**
   - `news_ratings` テーブルの作成。
   - ニュース配信時に評価ボタンを表示する `View` の実装。
2. **Phase 2: 集計ロジック実装**
   - 重み付き平均を算出する関数の作成。
   - 定期実行タスク内での集計処理の組み込み。
3. **Phase 3: プロンプト連携**
   - 集計結果を Gemini プロンプトに反映。
   - ニュース選定ロジックの最終調整。
